# 使用 Web 资料库

这页讲的是已经部署好的 Web 资料库如何使用：登录、保存视频、搜索、查看字幕
依据和管理条目。部署者请先看[部署独立前端](deploy-frontend.md)；Web 只展示
当前登录租户的资料，不是公开的视频搜索站。

## 1. 登录

打开管理员提供的精确 HTTPS origin，例如 `https://kb.example.com`，不要把 API
地址、MCP 地址或 loopback 地址直接当作浏览器入口。登录页会根据部署能力显示
可用方式：生产邮件登录使用一次性 6 位验证码；保留的渠道登录可能显示 Telegram
或微信批准流程。

安全地完成登录：

1. 确认地址栏是预期的 HTTPS origin，并且没有拼接 token 的 query 参数。
2. 输入自己的邮箱或按页面提示发起渠道登录。
3. 只在受信任的邮件、Telegram 或微信会话中查看验证码/批准请求。
4. 回到同一个浏览器 origin 完成验证，进入“我的视频资料库”。

生产 Web 登录必须由部署者配置 `WEB_AUTH_ENABLED=true`、精确的
`WEB_PUBLIC_ORIGIN`、至少 32 个字符的 `WEB_AUTH_SECRET`、`WEB_COOKIE_SECURE=true`
和邮件 provider；这些是部署条件，不要在浏览器端绕过。完整变量说明见
[环境变量参考](../reference/configuration.md)。

不要把验证码、session cookie、CSRF cookie 或浏览器开发者工具中的请求头复制到
聊天、Issue、截图或日志。若怀疑账号或设备泄露，先退出并联系部署者撤销 session。

## 2. 添加视频

在资料库点击“添加视频”，一次最多输入 10 个链接。输入框支持按 Enter 把链接
变成可移除的标签，也支持一次粘贴多行；可选填写“备注”或选择一个收藏夹标签。

服务器端添加支持：

- YouTube 普通视频链接；
- Bilibili 普通视频链接；
- 对当前账号可访问、且服务端能够取得字幕的内容。

提交后不要反复点击提交。服务会先返回 `等待整理`，条目再经过 `正在整理`，有
可用字幕并完成索引后才变为 `可阅读`。同一个视频已经存在时，页面会提示已有条目。
配额、队列不可用和来源暂不支持会显示不同的错误状态；按提示处理，不要把失败
状态当作已完成的知识导入。

NTULearn/Kaltura，或服务器无法直接读取字幕的 YouTube 页面，应使用[浏览器伴侣](use-browser-companion.md)。
ASR 不是普通 URL 添加的通用后备路径；没有字幕的条目会进入需要进一步处理的状态。

## 3. 浏览、筛选和搜索

资料库页面按区域展示“可阅读”和“正在整理”的条目。你可以：

- 在搜索框中输入标题、作者或备注；输入时会出现本地建议，选择建议后再请求服务器；
- 按 `可阅读`、`等待整理`、`正在整理`、`字幕不可用`、`整理失败` 或 `已归档` 筛选；
- 按最近添加、最早添加或标题排序；
- 点击收藏夹标签，只显示该标签对应的条目。

搜索只在自己的资料库内执行。它不会查询全网，也不会因为记得某个标题就访问另一个
租户的条目。

## 4. 查看视频和依据

点击条目进入详情页，先检查标题、作者、来源和整理状态，再打开字幕/Transcript。
完成整理的内容会以分页方式显示字幕片段和时间点；从时间戳链接返回原视频时，仍会
跳回对应位置。标题、字幕内容和来源状态由服务端保存，不要根据封面或模型摘要推断
未显示的章节。

在资料库点击“AI 智能检索”可以询问已经保存的视频。高质量回答会附带原文依据、
来源标题和可跳转的时间点；如果没有足够证据，界面应显示无依据/暂不可用，而不是
编造来源。回答只使用当前租户的 ready 条目。

## 5. 管理条目

在详情页或条目操作菜单中：

- 更新备注或收藏夹标签；
- 归档暂时不想看的内容；
- 从“已归档”筛选中恢复条目；
- 对整理失败的条目执行重试。

归档不会把内容变成另一个用户可见；重试也不会改变来源权限。后台处理中时不要
重复新增同一链接，先等待原 dispatch 的状态更新。

## 6. 退出与设备管理

使用账号菜单退出登录。若使用浏览器伴侣，打开“浏览器伴侣”页面查看已连接设备，
不再使用的设备点击“断开连接”；这会撤销该设备的 capture grant，但不会删除资料库
条目。浏览器伴侣的具体操作见[使用浏览器伴侣](use-browser-companion.md)。

# ASR 语音转写工作量与成本调研

## 目标

确定把处于 `needs_asr` 状态的条目转成可检索、带时间戳文本的最小可行路径，并在批准实施前量化工程工作量、供应商费用、基础设施成本和运营风险。

## 用户价值

- 没有可用字幕的视频最终也能被 Notebook Agent 检索和使用。
- 团队可以根据明确的用量与隐私取舍，在托管 ASR 服务和自托管 Whisper 之间做选择。
- 评估不会把语音识别简化成一次 API 调用，而是完整覆盖音频获取、上传、生命周期、清理、配额和时间戳保留。

## 已确认事实

- 连接器和 Worker 已有 `NeedsASR` 模型，并会把无字幕条目推进到 `needs_asr`（`app/connectors/base.py`、`app/ingest/tasks.py`）。
- 浏览器采集已经能持久化“字幕不可用”结果，并在不远程获取媒体的情况下完成现有调度（`app/browser_capture_submission.py`、`app/ingest/tasks.py`）。
- 当前 `capture.v1` 请求只接受元数据和字幕片段；音视频字段会被拒绝，扩展目前只提交一个 JSON 请求（`app/browser_capture.py`、`extension/src/protocol.ts`、`extension/src/worker.ts`）。
- 扩展目前只有页面脚本、存储及精确域名权限，没有音频上传或断点续传协议（`extension/manifest.json`）。
- ASR 返回带时间戳文本后，可以复用现有的标准化片段、对象存储、分块、向量化、全文展示和时间戳引用能力。
- 生产环境运行普通 CPU Celery Worker，并使用 Redis 和 MinIO；当前没有 GPU 运行时、ASR 模型、音频解码/转码器、独立 ASR 队列或 ASR 供应商依赖（`pyproject.toml`、`deploy/systemd/notebook-agent-worker.service`、`deploy/compose/production-dependencies.yml`）。
- `needs_asr` 在 Web 端只投影成通用的 `needs_action`，目前没有启动转写的用户操作，也没有 ASR 进度或费用状态（`app/web/library.py`、`web/src/videos/VideoDetailView.tsx`）。
- 浏览器伴侣任务曾明确把浏览器音视频采集、媒体上传、断点续传和后端 ASR 执行列为延期能力；本任务只把它作为仓库证据，不与该任务建立父子关系（`.trellis/tasks/08-14-browser-companion-video-ingestion/`）。

## 需求

### R1. 工作量估算

- 映射来源音频获取、有界/断点续传上传、对象存储、供应商执行、时间戳拼接、生命周期收敛、界面、配额、可观测性、隐私、测试和上线所需工作。
- 至少分别估算以下范围：
  1. 仅做可行性基准测试；
  2. 面向后端可获取的公开 YouTube 音频，使用托管 ASR 的 MVP；
  3. 面向浏览器采集的 YouTube 和私有 NTULearn/Kaltura 音频，使用托管 ASR 的完整产品路径；
  4. 自托管 Whisper 方案。
- 明确每项估算的假设、依赖和置信度。

### R2. 成本模型

- 比较托管 ASR 的每音频小时价格，以及每月 100、1,000 和 10,000 音频小时的费用。
- 说明各价格对应的模型是否能返回适用于现有引用能力的时间戳。
- 将压缩音频体积、临时对象存储和自托管 GPU 算力，与工程和运营成本分开估算。
- 记录公开价格的来源链接和查询日期。

### R3. 建议方案

- 给出分阶段路径，明确首个实验、供应商选择标准、费用保险丝、音频保留策略，以及重新评估自托管的触发点。
- 将托管供应商隐藏在适配层之后，使基准测试可以改变最终供应商而不改变摄取协议。
- 标明实施前仍会显著改变范围的产品或隐私决策。

## 验收标准

- [x] 已通过文件定位说明当前仓库中可复用的能力和缺失的数据链路组件。
- [x] 工程估算覆盖基准测试、窄范围托管 ASR MVP、完整浏览器伴侣路径和自托管方案。
- [x] 成本模型覆盖带时间戳的供应商选项、三个每月用量档位、压缩音频/存储假设和自托管算力限制。
- [x] 建议包含基准测试门槛、音频短期保留、独立 ASR 并发/费用上限和供应商适配层。
- [x] 定价和性能结论均附来源，并记录查询日期。
- [ ] 产品负责人确认第一版必须覆盖私有 NTULearn/Kaltura，还是可以先从更窄的视频来源范围开始。

## 不在范围内

- 在本调研任务中实现音频提取、上传、ASR 执行、数据库迁移、界面变更或生产基础设施。
- 签订供应商合同、购买 GPU 容量或把私有课程媒体发送给第三方。
- 实时麦克风/通话转写、直播字幕、说话人识别、翻译和人工编辑文本。
- 绕过认证、DRM、访问控制、平台限制或媒体权利。

## 仍需确认的规划决策

第一版实施范围需要在“公开、后端可获取的媒体”和“包含私有 NTULearn/Kaltura 的浏览器上传路径”之间做选择。后者的工作量明显更大。本调研报告已经分别量化两条路径，作出选择后无需再进行一次同类技术发现。

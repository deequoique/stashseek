# ASR 语音转写工作量与成本评估

调研日期：2026-08-20
置信度：工程量区间为中等；仓库事实和有引用的公开价格为高；在完成 YouTube 与 NTULearn/Kaltura 的真实媒体探针前，浏览器媒体提取为中低。

## 执行结论

Notebook Agent 已经具备 ASR 链路的后半段：持久化的 `needs_asr` 状态、租户归属条目、对象存储、带时间戳片段标准化、分块、向量化、全文展示和完成通知。但成本较高的前半段仍然缺失：从 YouTube/Kaltura 获取音频、安全上传大媒体、执行 ASR、拼接时间戳、控制费用，以及把条目从 `needs_asr` 重新送回常规摄取链路。

建议首个生产方案使用“托管的预录音频 ASR 适配层”，要求模型原生返回时间戳，音频只短期保留，使用独立且低并发的 `asr` 队列，并设置严格的单用户时长上限。从纸面能力看，Deepgram Nova-3 与当前时间戳协议最匹配；OpenAI Whisper 也可作为备选，但单文件不得超过 25 MB。正式实现前，应先用 2–4 天对英语、普通话、中英混说、课程讲解和低质量音频做基准测试，再决定供应商。

按一名熟悉本仓库的工程师估算：

| 范围 | 工程量估算 | 日历时间理解 | 置信度 |
|---|---:|---:|---|
| 使用人工提供的测试音频做离线可行性基准测试 | 2–4 个工程日 | 1 周以内 | 高 |
| 后端获取公开 YouTube 音频并使用托管 ASR | 11–17 个工程日 | 约 3–4 周 | 中；生产 IP 限流仍是主要限制 |
| 通过浏览器获取/上传 YouTube 和 NTULearn/Kaltura 音频并使用托管 ASR | 23–36 个工程日 | 约 5–8 周 | 中低；需先验证媒体适配器 |
| 在上一条完整产品路径上改用自托管 Whisper | 30–48 个工程日 | 约 7–10 周 | 中 |

以上是“实现加测试”的估算，不是只计算编码时间的乐观数字。假设条件包括：一名熟悉本仓库的工程师、不绕过 DRM，并复用现有浏览器配对、MinIO、Celery、标准化文本、摄取链路和 Web 界面。

## 为什么本项目的 ASR 不只是一次 API 调用

```text
受支持的视频页面
  -> 在不把 Cookie/令牌导出浏览器的前提下获取已授权音频
  -> 标准化/转码为有界的单声道音频
  -> 断点续传到具备租户边界的临时对象存储
  -> 持久化 ASR 任务 + 独立队列 + 配额/费用准入
  -> 调用供应商或 GPU Worker，并执行有界重试
  -> 校验带时间戳的词/片段并拼接分片偏移
  -> 转换为 capture-transcript.v1 标准片段
  -> 复用现有分块/向量化/完成通知链路
  -> 删除临时音频并开放可检索文本
```

当前流程在页面返回 `caption.status="unavailable"` 后立刻停止：Worker 把 `ContentItem.state` 设为 `needs_asr` 并返回。现有扩展 JSON 协议拒绝媒体；`BrowserCapture` 只能引用标准化文本对象，不能引用音频资产或 ASR 任务。生产 Worker 没有 GPU 或媒体运行时，Web 生命周期也没有 `start_asr`、进度、取消或费用/配额操作。

## 可复用能力与新增工作

### 可复用

- 扩展配对、租户限定的 Bearer 授权、精确 Origin 边界和幂等采集准入。
- `needs_asr` 终态和完成通知。
- MinIO/S3 对象存储抽象，但需新增分片上传和预签名上传方法。
- 标准化的带时间戳片段格式及文本解析器。
- 文本限制校验、分块、向量化、条目就绪、检索和时间戳界面。
- Celery/Redis 部署模式及发布准入脚本。

### 需要新增

- 各平台的媒体发现/下载，包括分段 DASH/HLS 和短时有效的 Kaltura 授权。
- 一个能表示“申请音频上传”的协议版本，同时拒绝第三方 Cookie、签名 URL 和 JSON 中的原始媒体。
- 直传/断点续传分片上传，以及字节数、时长、MIME、租户前缀、幂等、清理意图、过期和孤儿对象修复。
- 音频标准化和供应商安全分片；64 kbps 单声道音频约为 28.8 MB/小时。
- 持久化 ASR 任务状态、独立 `asr` 队列/并发、取消/重试、费用记录，以及每用户每月时长配额。
- 托管供应商客户端或自托管模型 Worker、时间戳校验、分片偏移拼接、语言处理和供应商错误映射。
- 从 `needs_asr` 收敛到标准化文本，再回到现有分块/向量化完成链路，同时避免生成重复片段或调度。
- Web/扩展中的同意、上传、排队/转写中、失败、超配额、重试和完成状态。
- 面向私有课程音频和第三方处理的安全/隐私评审；音频必须在短且明确的恢复窗口后删除。

## 工程工作拆分

下表中的组件在不同范围下存在重叠，窄范围后端获取方案不应把所有项目简单相加。

| 工作流 | 托管 ASR 浏览器路径 | 自托管额外工作 | 主要不确定性 |
|---|---:|---:|---|
| 产品/隐私协议、保留策略、配额、安全错误 | 1–2 天 | — | 私有 NTU 媒体能否发给第三方 |
| YouTube 音频适配器和真实页面夹具测试 | 3–5 天 | — | 播放器/DASH 变化，以及浏览器获取还是后端获取 |
| Kaltura/NTULearn 音频适配器和真实页面夹具测试 | 4–7 天 | — | 签名清单、分段媒体、页面变体和课程授权 |
| 断点续传直传、对象生命周期、孤儿清理 | 4–6 天 | — | 浏览器重启/重试及大文件失败窗口 |
| ASR 任务模型、队列、配额/费用准入 | 3–5 天 | 1–2 天 | 生命周期结构和迁移兼容性 |
| 托管供应商适配层、分片、重试、时间戳拼接 | 3–5 天 | — | 长文件行为和混合语言准确率 |
| 标准化文本收敛和摄取链路复用 | 2–4 天 | — | ASR 完成与向量化重试之间的幂等性 |
| Web/扩展进度、同意和恢复界面 | 2–4 天 | — | 自动上传还是明确的付费操作 |
| 自动化测试、隐私审计、预发布/真实试点 | 4–6 天 | 2–3 天 | 可靠且脱敏的媒体夹具 |
| GPU 容器/模型服务、预热、伸缩和监控 | — | 5–8 天 | CUDA/模型打包、冷启动、容量和显存溢出 |

考虑重叠后，完整托管浏览器路径总计 23–36 个工程日。自托管增加约 7–12 个工程日，并带来持续 GPU 运维。只支持后端可获取的公开 YouTube，可以省掉浏览器断点续传和 Kaltura 工作，总量降到 11–17 天；但它会继承本仓库已知的生产 IP 限流问题，而且无法处理私有 NTULearn 媒体。

## 供应商费用与协议匹配度

以下均为 2026-08-20 查询到的公开按量价格，不含税、区域加价、存储、网络出口和可选附加功能。

| 方案 | 公开价格 | 每音频小时成本 | 时间戳匹配度 | 重要边界 |
|---|---:|---:|---|---|
| OpenAI `gpt-4o-mini-transcribe` | $0.003/分钟 | $0.18 | 不适合本产品 | OpenAI 最便宜的转写方案，但文件转写文档要求需要时间戳的场景使用 Whisper，而不是此模型。 |
| OpenAI `gpt-transcribe` | $0.0045/分钟 | $0.27 | 不适合本产品 | OpenAI 推荐的一般文件转写模型，但不提供本项目所需的原生词级/片段级时间戳协议。 |
| OpenAI Whisper（`whisper-1`） | $0.006/分钟 | $0.36 | 良好 | 支持词级/片段级时间戳；单文件限制为 25 MB，更大的音频必须压缩或切分。 |
| Deepgram Nova-3 单语 | $0.0043/分钟 | $0.258 | 良好 | 返回每个词的开始/结束时间和置信度；适合已知为单一语言的音频。 |
| Deepgram Nova-3 多语 | $0.0052/分钟 | $0.312 | 良好 | 从纸面能力看更适合英语/普通话/中英混说。预录音频文件最大 2 GB，但同步请求超过 10 分钟可能超时，因此仍需回调或有界分片。其公开定价页说明列出的价格会加入 Model Improvement Program，这可能不适用于私有课程音频。 |
| 按需 GPU 上自托管 faster-whisper | 仅算力约 $0.006–$0.035/音频小时 | $0.006–$0.035 | 良好 | 采用保守的 20–49 倍实时速度，并以 $0.27/小时 A5000 Pod 到 $0.69/小时 24 GB Serverless GPU 测算；不含冷启动、空闲容量、存储、出口、工程、监控和失败任务。 |

faster-whisper 项目公布的基准显示：在 RTX 3070 Ti 上使用 large-v2 时，13 分钟音频根据批处理/精度不同需要 16–63 秒，约为 12–49 倍实时速度。本成本模型对优化后的 GPU 路径使用更保守的 20–49 倍区间，并不声称所有托管 GPU 或语言组合都能达到同样吞吐。

### 每月变量成本示例

带时间戳的托管方案对比采用 Deepgram Nova-3 多语和 OpenAI Whisper。自托管数字只包含算力，并假设真正按需、可缩至零；持续运行 GPU 的成本另行说明。

| 每月处理音频 | OpenAI Whisper | Deepgram Nova-3 多语 | 自托管 GPU 纯算力 | 64 kbps 压缩音频产生量 |
|---:|---:|---:|---:|---:|
| 100 小时 | $36 | $31.20 | 约 $0.60–$3.50 | 2.88 GB |
| 1,000 小时 | $360 | $312 | 约 $6–$35 | 28.8 GB |
| 10,000 小时 | $3,600 | $3,120 | 约 $60–$350 | 288 GB |

如果 $0.27/小时的 A5000 级 Pod 整月持续运行，仅算力约为 $194/月。与 Deepgram 多语的变量费用相比，交叉点约为 623 音频小时/月，但这里尚未计入工程和运维。可缩至零的 GPU 算力在更低用量下看起来就更便宜，但额外 7–12 个工程日会在很长一段时间内主导总成本。设内部单个工程日成本为 `D` 美元，近似盈亏平衡点为：

```text
盈亏平衡音频小时 ≈ (7 到 12) × D / (托管每小时费用 − 自托管每小时算力)
```

例如，按 $500/工程日、每音频小时节省 $0.28 计算，仅摊销工程成本就需要累计约 12,500–21,400 音频小时。这也是不建议 MVP 默认自托管的原因：它应由真实用量或隐私要求触发。

### 存储与带宽

- 64 kbps 单声道语音约为 28.8 MB/小时，96 kbps 约为 43.2 MB/小时。能提取音频时，不应保留源视频。
- OpenAI 的 25 MB 上传限制意味着，即使使用 64 kbps，一小时音频仍至少要分成两个文件。供应商无关的 5–10 分钟分片策略更便于重试、时间戳偏移和供应商切换。
- 若只保留 24 小时，稳态临时存储约等于一天的摄取量，而不是整月用量。标准化片段保存后，永久保留音频只会增加隐私风险，不会改善 Notebook Agent 能力。
- 浏览器向 Notebook Agent 上传会消耗用户上行带宽。供应商出口费用取决于 Worker 上传字节，还是供应商拉取临时 URL；私有 MinIO 对象不得被长期公开。

## 建议的交付策略

### 门槛 0：2–4 天基准测试

使用 12–20 个已获授权的样本，覆盖：

- 清晰的英语课程讲解；
- 普通话，以及中英混说；
- 新加坡口音/Singlish；
- 差麦克风、音乐/噪声和长时间静音；
- 30–120 分钟的录音；
- 与用户真实 NTU/课程资料相关的术语。

比较 Deepgram Nova-3 多语、OpenAI Whisper 和 faster-whisper large-v3/turbo 的文本准确率、时间戳漂移、标点、混合语言、延迟、失败行为和实际计费分钟。用户批准处理方和隐私边界前，不要上传私有课程录音；首轮测试使用合成样本或自有样本即可。

### 门槛 1：托管 ASR 数据链路

- 引入 ASR 供应商接口，统一返回经过校验的带时间戳片段，以及语言/供应商元数据。
- 增加独立 `asr` 队列，并采用保守并发（例如 1–2 个任务），避免长媒体阻塞现有字幕摄取和维护队列。
- 对可能产生费用的转写要求明确用户操作/同意；执行单条时长和每用户每月分钟上限；只暴露安全错误类别。
- 通过具备租户前缀的临时对象存储直接断点续传；Web API 应签发有界上传意图，而不是让请求进程代理数百 MB 数据。
- 媒体 I/O 前持久化清理意图。标准化文本成功落库后删除音频；失败任务仅保留一个较短的恢复 TTL。
- 将供应商输出标准化为现有 `capture-transcript.v1` 片段，并复用当前校验/分块/向量化/读取/引用链路。
- 记录申请时长、接受时长、供应商/模型、计费分钟、延迟、结果和重试次数，但不记录音频、文本、签名 URL 或凭证。

### 门槛 2：浏览器媒体适配器

在承诺完整估算前先做小范围真实探针：

1. 在用户操作下提取一个公开 YouTube 的纯音频流，不导出 Cookie 或签名媒体 URL。
2. 提取一个用户有权访问的 NTULearn/Kaltura 音频，并证明所有页面级令牌只在本地消费并立即丢弃。
3. 分片上传一个 60–120 分钟样本，中断并重启扩展，验证幂等续传和孤儿对象清理。

如果任一平台探针失败，应缩小支持来源范围，而不是放宽认证或 DRM 边界。

### 门槛 3：重新评估自托管

只有至少满足以下一项时，才重新考虑 faster-whisper：

- 持续用量使托管变量费用显著高于实测工程和运维值班成本；
- 私有课程音频不能发送给所选托管处理方；
- 托管服务的实测准确率/延迟无法接受，而自托管模型在基准集上证明更优；
- GPU 容量能与其他自有工作负载共享，同时不破坏 ASR 延迟和隔离。

## 风险与决策

### 影响最大的产品决策

第一版是否包含私有 NTULearn/Kaltura 音频，会把估算从约 11–17 天提高到 23–36 天。私有 Kaltura 必须在浏览器上下文获取媒体，并建设断点续传数据链路；只做后端 YouTube 无法替代这条能力。

### 隐私与平台政策

字幕和原始音频不是同等级数据。私有课程录音可能包含教师/学生声音及课程材料。使用托管处理方需要清晰披露、获批的保留策略、确认学校/内容权利方允许第三方处理，并确保供应商条款不会以不兼容方式复用媒体。Deepgram 公开定价页说明列出的价格会加入 Model Improvement Program；不训练或企业方案的可用性和价格可能不同。实现不得上传 Cookie、SAML 响应、Kaltura KS、签名清单或 YouTube 会话材料。

### 平台脆弱性

YouTube 和 Kaltura 的媒体关系图不是官方浏览器集成接口，会发生变化。必须有真实脱敏夹具、适配器诊断、精确域名和可恢复的 `audio_capture_unavailable` 行为。遇到 DRM 或访问控制必须停止，不能把绕过当成缺陷修复。

### 费用滥用

音频时长会直接产生账单，仅做身份认证不够。向供应商提交前，准入层必须检查时长、租户配额、并发任务、月度预算、幂等键和重试上限。

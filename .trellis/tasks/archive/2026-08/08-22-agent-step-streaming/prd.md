# 逐步可见的 Agent 流式输出

## Goal

把现有“阶段标签 + 最终答案正文流式”的体验升级为 Agent 执行过程持续可见的流式体验。用户在等待最终答案期间，应能像使用 Codex、Hermes、Claude 一样，连续看到当前步骤、工具活动、步骤结果和回答生成，而不是长时间停留在一个笼统状态。

## Background

- 浏览器已经通过 SSE 接收严格递增的公开事件，并具备请求标识、消息标识、断线失败、终态屏障和非流式降级。
- 当前公开事件包含 `started`、受控 `activity`、回答 section 生命周期、`text_delta` 和终态。
- 最终回答已经支持 Citation 先行的 provider 文本增量；前端会按 section 实时追加正文。
- 主要缺口发生在主 Agent 的检索/工具循环：`KnowledgeAgent.stream()` 仍等待 `_run_primary_agent()` 完整返回，期间前端通常只显示“正在检索资料库…”，单次或多次搜索、读取相邻片段、查看条目、库存操作、Todo 变化等都不可见。
- 当前 PydanticAI 2.15.0 提供 `run_stream_events()`、函数工具开始/结果事件和最终结果事件，因此运行时具备在不启动第二次 Agent 执行的前提下逐步消费生命周期的基础能力。
- 现有信任边界明确禁止把 provider 原始事件、系统提示词、隐藏推理、原始工具参数和工具 payload 直接发送到浏览器。

## Requirements

1. 一次 Agent 请求从开始到终态持续发送公开执行步骤，不再把整个主 Agent 工具循环压缩成单个“retrieving”活动标签。
2. 至少可见以下用户可理解的过程：准备、模型选择下一步、工具开始、工具完成/失败、检索或读取结果摘要、Todo/计划进度（如本轮实际使用）、回答规划、回答正文增量、完成/失败/取消。
3. 每个步骤具有稳定 ID、顺序、类型、状态和受控展示文案；同一工具调用的开始与结果可以关联，前端能把运行中的步骤原位更新为成功或失败。
4. 工具名称、输入摘要和结果摘要必须通过服务端 allow-list 投影。不得直接转发模型生成的工具参数、数据库/租户/内部 ID、原始检索正文、异常消息或完整工具返回值。
5. 不公开系统提示词、provider 原始事件、模型 metadata、隐藏 chain-of-thought 或未经专门安全设计的 reasoning 文本。
6. 保留现有 Citation 先行的回答 section 流、最终 `ConversationResponse` 权威校正、单次持久化、message 幂等、取消/断线和非流式兼容行为。
7. 前端把执行过程呈现为一条可扫描的时间线/步骤列表，而不是不断覆盖同一行状态文字；答案开始生成后，过程记录仍可查看但不抢夺正文视觉层级。
8. 对重复、乱序、缺口、未知工具、工具失败、流中断、取消和终态后尾随事件保持确定的失败关闭或幂等行为。
9. 增加不含正文与参数的可观测性：步骤类型、工具公开类别、耗时、结果数量、终态和 fallback 原因。

## Acceptance Criteria

- [ ] 使用含两次以上工具调用的 fake Agent 时，`completed` 前按真实发生时间收到可关联的工具开始与工具结果步骤，而不是 Agent 完成后批量补发。
- [ ] 用户能看到至少一条具体、可理解的检索/读取步骤及其安全结果摘要，例如“搜索资料库”→“找到 5 个相关片段”；不会看到原始 query、segment/item ID、字幕正文或工具 JSON。
- [ ] 多步骤 Todo 被实际采用时，用户能看到其状态推进；未采用 Todo 的简单请求不会伪造计划。
- [ ] 回答正文继续按现有 section/Citation 生命周期增量显示，最终终态响应与历史持久化完全一致且只保存一次。
- [ ] 未知或未 allow-list 的工具只显示通用安全活动，不泄漏名称、参数或结果；失败只显示固定错误类别。
- [ ] provider thinking/reasoning、系统提示词、工具原始参数/返回、异常消息、跨 tenant 内容和敏感哨兵均不会进入公开 SSE、DOM 或生产日志。
- [ ] 客户端取消、网络断开、超时、乱序/缺口和终态尾随事件均有自动化测试，且不会留下永久 pending 步骤或持久化半截答案。
- [ ] 简单回答、Action、无证据、provider 不支持 answer token streaming、SSE disabled 和 JSON 客户端保持兼容。
- [ ] 前端时间线具备可访问的状态语义、键盘可用性和 `prefers-reduced-motion` 兼容；移动端不撑坏布局。

## Out of Scope

- 把 chain-of-thought、provider thinking token、系统提示词或原始工具 payload 原样展示给用户。
- 改变检索预算、tenant 授权、Citation 校验、Action 确认语义或会话持久化模型。
- 为了制造“过程感”虚构未实际发生的步骤、固定延迟或伪造 token 粒度。
- 在本任务中引入新的 Agent 框架或替换 SSE 传输。

## Key Decisions

- “每一步”采用 Codex/Claude 式的安全执行时间线：展示真实发生的受控步骤摘要、工具开始/结果、Todo 和回答增量。
- 明确不展示原始隐藏推理、provider thinking、系统提示词、原始工具参数或完整工具结果。
- 继续使用现有 SSE 和单次 Agent 执行；不通过轮询、第二次模型调用或人工延迟制造过程感。

## 核心流程

```text
视频/字幕元数据
  -> provider 识别
  -> provider-neutral normalization
  -> 自动 contract checks + 弱参考指标
  -> 风险评分
  -> 固定小样本人工抽查
  -> 脱敏 trace / 评估记录（可选外部平台）
```

自动检查负责回答“结果是否可用、是否稳定、是否可检索”；人工抽查负责回答
“这个结果是否真的符合画面/语音”。两者不再共用一份需要逐条维护的 truth。

## 代理指标

- ASR：字幕重叠率、关键词命中、时间戳边界合法性、简繁归一化后检索命中、重复运行一致性。
- Vision：结构化字段完整率、frame 时间合法性、同 bundle 场景一致性、标签/标题与元数据的语义相似度。
- OCR：坐标合法率、文字非空率、跨重复帧稳定性、与硬字幕/可见 UI 文本的弱匹配率。
- 全模态：schema 通过率、跨视频证据污染率、失败分类、P50/P95 延迟和用量。

代理指标只能作为筛选和回归信号，不能冒充人工准确率。

## 抽样规则

每个模态每轮固定抽查少量样本，优先抽：低置信度、代理指标冲突、长/噪声/密集 UI、跨语言、模型版本变化和历史失败样本。连续通过时减少抽查；出现系统性失败时自动扩大到该风险 strata。

## 工具选型原则

首期保留仓库内确定性 evaluator 作为事实来源。LangSmith 可作为 LLM trace、dataset、LLM-as-judge 和人工反馈层；Phoenix 更适合开源/自托管 tracing 与实验分析；Braintrust 更偏评估集、评分器和人工 review 工作流。三者都不能替代视频切片、时间戳校验和敏感媒体治理。

推荐顺序：先本地 evaluator，随后以 LangSmith 或 Phoenix 做可选观测层；只有当人工 review 分发、团队协作或长期回归规模明显增加时，再评估 Braintrust。

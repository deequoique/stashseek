# 回答内嵌可收起的引用按钮，去掉成篇的依据列表

本文只写需求、约束和验收标准。技术方案写在 `design.md`，执行计划写在 `implement.md`，两份等本 PRD 确认后再写。

## 目标

资料库问答的回答里，每处引用就是一个小按钮，长在它所支撑的那句话旁边；点一下直接跳到原视频的对应时间点；不想看时可以一键收起。回答下方那块成篇的"依据 N"列表不再显示。

用户价值：引用和论断贴在一起，读起来不用在正文和列表之间来回对；界面更短，手机上尤其明显。

## 背景与现状

下面的事实已在 dev 分支（2026-10-20）确认。

- **正文里的标记是纯文字。** 服务器在校验引用后把 `[S<segment_id>]` 原样写进回答文本；前端 `extension/src/chat/MarkdownAnswer.tsx` 用 react-markdown 渲染，标记显示为 `[S1691]` 这样的字符串，不可点击。
- **依据列表在回答下方。** `extension/src/chat/ChatPage.tsx` 的 `CitationList`（第 136–153 行）渲染有序列表：序号、标题、时间点（`53:45 ↗`，没有时间点时显示 `打开 ↗`）、以及默认折叠的"展开字幕依据"。标题行 `<header>` 显示"资料库回答"和"依据 N"（第 769 行），列表上方还有一行"依据 N · 可跳转原视频，字幕默认折叠"（第 775 行）。流式回答按段（section）渲染时也各带一份 `CitationList`（第 795–800 行）。
- **浏览器拿不到标记与列表的对应关系。** 公开的引用结构 `ConversationCitationResponse`（`app/api/conversation_routes.py:142-150`）只有 `title`、`excerpt`、`url`、`start_sec`，有意不带内部 ID。所以前端无法把 `[S1691]` 对到列表第几条。
- **引用顺序是服务器定的。** 来源区块和引用列表都按检索保留的顺序排列（`app/agent/answer_pipeline.py` 的 `_append_sources`，规范 `agent-retrieval-convergence.md`）。网页端从回答文本里剥掉"来源："区块（`ChatPage.tsx` 的 `assistantTextWithoutSourceList`）。
- **流式输出有标记保护。** `_StreamingTextGuard`（`answer_pipeline.py`）会扣住可能被切断的 `[S…` 前缀，等完整标记到齐再放出，所以标记不会被拆到两个 `text_delta` 里。
- **标题行引用。** 任务 `10-20-cn-recall-fusion` 之后，引用可能是条目的"标题与简介"（`kind="title"`，`start_sec` 为空，链接不带时间点）。
- **线上网页是 main 的 `web/` 构建的**（`web/src/chat/ChatPage.tsx`、`MarkdownAnswer.tsx` 与 dev 的 `extension/src/chat/` 同源）。改动要在 dev 提交后移植到 release 分支再合并 main（参照 PR #34/#35）。
- 插件的 pnpm 需要 Node 22（默认 nvm 的 v20 会让 pnpm 11 崩溃）。
- 用户 2026-10-20 的决定：引用做成内嵌小按钮，点击跳转，可收起；下方成篇的依据列表去掉。

## 需求

### R1 服务器把正文标记改成顺序编号

- 网页接口（最终回答、流式分段、历史记录）返回给浏览器的回答文本里，`[S<segment_id>]` 改为 `[1]`、`[2]`……编号等于该引用在同一条回答的引用列表里的位置（从 1 起）。同一个片段在正文里多次出现用同一个编号。
- 编号在服务器端完成，浏览器永远看不到内部 ID；持久化的回答文本是否保留 `[S…]` 在 `design.md` 决定，但对外形状必须一致：历史记录和刚生成的回答看起来一样。
- 流式分段：每段的编号按整条回答的引用列表统一编号，不是每段从 1 重排。
- MCP、LangBot 等非网页通道的文本不变（仍是 `[S…]` 加"来源："区块）。

### R2 正文里的引用按钮

- 每个 `[n]` 渲染成一个小按钮，位置就在原标记处（句尾）。按钮上显示编号；鼠标悬停（或键盘聚焦）时显示该引用的标题、时间点和字幕原文摘录的前 120 字（用户 2026-10-20 决定：去掉列表后字幕原文只剩这一处可见，所以必须显示）。触屏没有悬停，点击即跳转。
- 点击在新标签页打开引用链接，和现在列表里的链接行为一致：有时间点的跳到时间点，标题行引用打开视频本身。
- 按钮是真正的链接（可用键盘访问、有可读的 aria 标签，例如"引用 3：《标题》 53:45"）。
- 连续多个引用（`[1][2][3]`）并排显示，彼此有间距，不换行拆散一句话。

### R3 可以收起

- 每条回答有一个小开关（例如回答标题行里的"引用 8"），点一下把正文里的所有引用按钮隐藏，只剩文字；再点一下恢复。默认显示。
- 收起只影响显示：正文文字不动，复制文本时仍带 `[n]` 编号（用户 2026-10-20 决定，便于追溯）。

### R4 去掉依据列表

- 删除回答下方的"依据 N"列表、"可跳转原视频，字幕默认折叠"提示和"展开字幕依据"折叠块，包括流式分段里的那份。
- 回答标题行里的"依据 N"保留并改为 R3 的开关。
- 没有引用的回答（无依据、失败、问候类）不显示开关。

### R5 线上网页同步

- dev 的 `extension/src/chat/` 改完后，按现有流程移植到 release 分支合并 main，线上网页与插件表现一致。

## 不在范围

- 视频页问答（侧边栏 `QaThread`）的引用样式。
- MCP、LangBot 文本格式。
- 引用的排序、数量或检索逻辑（任务 `10-20-cn-recall-fusion` 已处理）。
- 依据列表以外的聊天界面改版。

## 约束

- 在 dev 分支开发，按路径提交；线上网页另走 release 分支。
- 兼容旧插件：接口字段只增不改；已安装的插件在服务器改编号后仍能显示回答（它会把 `[1]` 当普通文字显示，可接受）。
- 隐私与日志契约不变。

# ASR 转写链路：Fun-ASR 默认 + whisper-1 备选

## 目标

公开 YouTube/Bilibili 视频如果没有可用字幕，现在会永久停在 `needs_asr`。本任务让这类视频在入库时自动完成以下流程，最终变成 `ready`：

1. 后端获取音频；
2. 用托管 ASR 生成带时间戳的转写；
3. 进入现有的切分、向量化、检索和引用链路。

## 背景与已确认决策

- **2026-10-15 用户确认**：
  - 视频方案改为“多模态 embedding + ASR”，独立的 Vision/OCR 识别已移除；
  - ASR 不再做模型测试；
  - 默认使用阿里云百炼 Fun-ASR，备选使用 OpenAI `whisper-1`。
  - 选型依据见 `archive/2026-10/08-24-intent-aware-video-recognition-routing/prd.md` 的“2026-10-15 方案变更”。
- **2026-10-15 用户确认的部署方案**：
  - Fun-ASR 使用**新加坡区域**（国际账号）；
  - 音频经**本应用域名下的短期签名下载地址**提供给 Fun-ASR；
  - **生产服务器安装 ffmpeg**。
- **从已归档的 08-24 父任务继承的决策**：
  - 只处理后端能直接、合规获取的公开视频；不使用 Cookie、登录态或私有/DRM 媒体；
  - 首期不做费用预算、额度或付费准入，但要记录用量和估算费用；
  - 无字幕视频自动处理，不需要逐条确认。
- **开发规范**：在 `dev` 分支开发，具体代码由 Sonnet 子 agent 编写。见 `.trellis/spec/guides/branch-and-delegation-workflow.md`。

## 需求

### R1. 触发

- 连接器对公开 YouTube 或 Bilibili 条目返回 `NeedsASR`，并且 ASR 已启用时，同一个 dispatch 自动转入独立的 `asr` 队列执行转写。此时不再以 `needs_asr` 结束，也不发送“需要语音识别”的通知。
- ASR 未启用、配置不完整或平台不支持时，行为与现在完全一致，条目仍以 `needs_asr` 结束。
- 浏览器伴侣采集的条目（包括 `ntu_kaltura` 和字幕不可用的 YouTube 采集）不进入 ASR。

### R2. 音频获取

- 后端用 yt-dlp 只下载音频流，并遵守以下限制：
  - YouTube 沿用现有的子进程专用代理和 CA 环境；
  - 不使用 Cookie 或令牌；
  - 下载文件只写入私有临时目录；
  - 时长、大小和超时都有上限。
- 时长超过上限的条目直接失败，并使用稳定的错误码，不调用任何供应商。
- 限流、代理不可用等临时错误沿用现有的 `TransientFetchError` 重试语义。

### R3. Fun-ASR（默认）

- 临时音频存入对象存储，再生成一个短期签名下载地址：
  - 地址在本应用公网域名下，默认 2 小时过期；
  - 只能下载这一个临时音频对象。
- 调用 Fun-ASR 的录音文件异步识别，提交任务后轮询结果，再把句级时间戳转换为转写片段。
- 不设置 `language_hints`，让模型自动识别语种，以兼容中英混说。

### R4. whisper-1（备选）

只在以下两种情况启用：

- Fun-ASR 不可用：缺少密钥、鉴权失败、服务错误、超时；
- 返回结果不符合协议：没有可用的时间戳句子，或格式错误。

Fun-ASR 正常返回“没有语音”时，**不**切换到备选。

长音频用 ffmpeg 转码并按时间切分，每片不超过 25MB；各片的时间戳按偏移拼接。没有 ffmpeg 时，备选只处理不超过 25MB 的音频。

### R5. 结果入库

- 转写结果保存为现有的 `capture-transcript.v1` 规范转写对象，然后复用现有的守卫、切分、向量化、Segment 写入和 `ready` 流程。
- 转写为空时，直接以稳定错误码 `asr_no_speech` 失败，不进入会重复计费的临时重试。
- 本任务**不新增数据库迁移**。
  - `text_source` 复用现有枚举值 `asr_whisper`，统一表示 ASR 转写；实际供应商记录在对象 key 和运行日志里。
  - 工作区的 Alembic 链目前包含未提交的 WeMM 迁移，等它整理好之后，再另行加入专用的枚举值。

### R6. 生命周期、清理与可观测性

- 转写期间，条目状态为 `fetching`，Web 端显示为处理中。完成后整个 dispatch 只产生一个完成事件和一条通知。
- 临时音频在转写结束后立即删除，无论成功还是失败。运维文档另外提供按前缀过期的兜底清理规则。
- 每次转写记录一条结构化日志，包含：
  - 供应商、模型、音频时长、计费时长、估算费用、耗时、是否使用备选、错误码；
  - **不包含**音频、转写文本、签名 URL、供应商原始响应或密钥。
- 新增的 ASR 错误码要加入 Web 与诊断的允许列表，不能被显示成笼统的 `ingestion_failed`。

### R7. 配置与上线

- 默认关闭（`ASR_ENABLED=false`）。只有开启后，才校验所需配置：
  - DashScope 密钥、公网基础 URL、签名密钥；
  - 可选的 OpenAI 密钥。
- 部署相关：
  - 新增独立的 `asr` worker（并发 1），并纳入部署脚本的停止、重启和回滚；
  - 本地启动器也要能消费 `asr` 队列；
  - 部署文档写明需要 ffmpeg，以及新的环境变量。
- 提供 operator 命令，把已有的 `needs_asr` 公开条目批量重新派发进 ASR 链路。命令要有数量上限，并支持 dry-run。

## 验收标准

- [ ] ASR 关闭时，`needs_asr` 的行为、通知和现有测试都保持不变。
- [ ] ASR 开启时，用 fake 连接器、fake 存储和 fake 供应商端到端证明：无字幕的 YouTube/Bilibili 条目，在同一个 dispatch 内经 `asr` 队列变成 `ready`，并且只产生一个 `completed/ready` 完成事件。
- [ ] Fun-ASR 客户端有 fake 传输测试，覆盖：提交、轮询、成功、子任务失败、超时、结果解析（毫秒转秒）和请求格式（异步头、`parameters` 字段、不发送 `language_hints`）。
- [ ] 备选触发条件可测：
  - 不可用或协议失败时切换到 whisper；
  - 转写为空时不切换，并以 `asr_no_speech` 失败；
  - whisper 的切分时间戳偏移拼接正确。
- [ ] 签名地址有以下测试：
  - 正确签名可以流式下载；
  - 过期、篡改、错误路径都返回 404；
  - 响应带 `Cache-Control: no-store`；
  - 路由不需要会话登录，也不会泄露对象 key。
- [ ] 无论成功、失败或异常，临时音频都会被删除。日志和错误信息中都没有 URL、密钥或文本。
- [ ] 下列配置都有测试：开启时缺少必需项会报错；关闭时不需要这些项；`asr` 队列、路由、systemd unit 和部署脚本。
- [ ] 回填命令有测试，覆盖 dry-run 和数量上限。
- [ ] 相关测试套件全部通过，测试的 `DATABASE_URL` 指向测试分支。
- [ ] 后端 spec 新增 ASR 转写契约文档。
- [ ] 改动只在 `dev` 上提交，并且只包含本任务的文件和 hunk。

## 不在范围内

- Vision/OCR、稀疏采样、发现索引、意图路由和异步识别续答。
- 浏览器采集音频上传，以及 NTULearn/Kaltura 或其他私有、登录态媒体。
- 部分字幕或低质量字幕的缺口补齐。目前只处理已经判定为无字幕的条目。
- 费用预算、额度和付费确认。
- 说话人分离、热词、翻译、简繁转换。
- 新增数据库迁移和专用的 `text_source` 枚举值，留作后续任务。
- 在生产环境实际开启 ASR，包括安装 ffmpeg、写入生产密钥、安装 unit。这需要合并到 `main` 并经用户批准后，由运维单独执行。

**口径说明**：

- 理想上限：在当前切块下，最优的 5 个片段能覆盖具体题金标准的 97.5%，概括题的 63.7%。

**会议定位**（范围 B，线上设置）：

## 3. 各项改动的效果（与同一范围的线上设置配对比较，具体题 n = 235）

| 设置 | 范围 | Recall@5 | ΔRecall@5 [95% CI] | Hit@5 | McNemar p |
|---|---|---|---|---|---|
| 关闭多样性（其余同线上） | B | 0.267 | **+0.091 [0.064, 0.120]** | 112/235 | < 0.001 |
| RRF + AND + 关闭多样性 | B | 0.271 | +0.095 [0.067, 0.125] | 113/235 | < 0.001 |

## 4. 与 val RQ1（n = 28）对照

| 指标（线上设置） | val 30 题 | test 全量具体题 |
|---|---|---|
| A Hit@5 / Recall@5 | 0.679 / 0.381 | 0.783 / 0.473 |
| B Hit@5 / Recall@5 | 0.250 / 0.090 | 0.404 / 0.176 |
| B 关闭多样性 Recall@5 | 0.210（p = 0.125，不显著） | 0.267（p < 0.001） |
| B 第一名是正确会议 | 13/28 | 121/235 |
| B 认错时同来源 | 12/15 | 105/114 |
| 理想上限 Recall@5 | 0.953 | 0.975 |

- test 的绝对值比 val 高。一个可能的原因是题目构成不同：val 的 30 题按领域平均抽取（每个领域 10 题），test 全量则以 AMI 为主。这一点没有单独验证。所有方向性结论在两边都一致。
- **val 时不显著、test 上确认的结论**：
  - 全库检索时关闭多样性有显著改进（+0.09，p < 0.001）。
  - OR 关键词检索没有帮助：在全库时显著变差，在已知会议时没有显著差异。
  - 换融合方式（RRF / min-max）基本没有作用：线上 AND 关键词检索几乎检索不到东西（单独使用时 Hit@5 只有 5/235），融合方式无从发挥。
  - 瓶颈在排序和会议定位，不在切块：理想上限 0.975，而线上实际只有 0.473（A）/ 0.176（B）。

## 5. 与 PPT 上 Agent 端到端数字的口径区别

PPT 上的 Hit@5 0.714 和候选池召回率 0.780，来自 2026-10-07 的 Agent 端到端运行，与本报告有两点不同：

1. 检索词是 Agent 自己写的，而且 Agent 会检索多次；
2. 每场会议一个账号，相当于范围 A。

本报告用原题检索一次。两组数字不能直接比较，应该放在不同的页上，或者在同一页上注明口径。

## 6. 建议（另建任务，不在本任务内）

1. **全库检索时关闭或放宽多样性处理**：test 上已显著（+0.09）。注意它会降低"前 5 条里有正确会议"的比例，需要配合 Agent 的二次检索一起评估。
2. **改进会议定位**：在两阶段检索中先选视频、再检索片段；视频级信号（标题、摘要、日期）参与排序；补说话人标签。AMI 这类系列会议是重点。
3. **关键词检索**：不改成 OR。AND 几乎不起作用，这个问题要单独解决，例如专名抽取或短语检索，而不是放宽匹配条件。
4. **Agent 端到端在全库场景下的真实损失**：Agent 能否通过二次检索弥补定位损失，仍需要单独测量。这属于任务 09-04 的范畴。

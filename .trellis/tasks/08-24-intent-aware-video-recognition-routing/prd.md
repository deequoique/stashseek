# 按意图按需分配视频识别能力

## 目标

把当前以字幕文本为中心的视频理解方案，演进为两层视频理解方案：视频入库时生成低成本、粗粒度的“发现索引”，保证用户能从大量视频中找到可能的目标；用户进一步追问某个视频时，再根据问题意图按需调用字幕、音频识别、图像识别或组合分析。方案需要同时控制入库成本、首次检索延迟和深度分析等待时间，并保留可信来源、时间定位和可恢复性。

## 用户价值

- 对只依赖语言内容的问题，不为整段视频额外运行视觉模型。
- 对“幻灯片写了什么”“演示做了什么”“这段是什么声音”等字幕无法回答的问题，可以按需补充对应模态。
- 对没有字幕的视频，不再只有永久停留在 `needs_asr` 这一种产品结果，而是可以在用户确实需要内容时触发受控识别。
- 已完成的识别结果可以安全复用，避免同一视频、同一时间范围被重复计费和重复等待。
- 大量视频的粗粒度定位不依赖临时运行昂贵模型，常规发现请求应先快速返回候选视频。
- 视觉处理服务于“找到视频和对应时间段”，不为了生成完整视频解说而预先理解每个画面。

## 已确认的当前状态

- YouTube、Bilibili 和浏览器伴侣均优先取得官方或自动字幕；没有字幕时，Worker 将条目标记为 `needs_asr`。
- 当前 `needs_asr` 只有状态模型，没有音频获取、媒体上传、ASR 任务、费用准入或结果回灌链路。
- 当前问答 Agent 的知识工具只检索已向量化的文本片段，回答引用也以字幕片段和时间戳为依据。
- 浏览器伴侣的 `capture.v1` 明确只接收元数据和字幕，不接收音频、视频或画面帧。
- 当前仓库没有画面抽帧、场景切分、OCR、视觉模型调用、视觉结果索引或画面引用协议。
- `.trellis/tasks/archive/2026-09/08-20-asr-workload-cost-research/` 已评估 ASR 前半段链路、托管/自托管成本和隐私边界，本任务应复用该结论，不重复把 ASR 当作一次普通 API 调用。

## 初步范围

### R1. 意图与能力路由

- 为视频内容问题定义稳定、可测试的需求分类，至少能表达：
  - 字幕/文本足够；
  - 需要音频转写或声音信息；
  - 需要画面、幻灯片、屏幕文字或动作信息；
  - 需要音频与画面的时序组合；
  - 信息不足，需要澄清或无法处理。
- 路由输出必须是结构化决策，包含所需模态、目标视频/时间范围、置信度或降级理由，不允许只依靠无法审计的自然语言判断。
- 采用已确认的混合模式：入库阶段负责粗粒度发现能力，提问阶段负责详细问题的模态路由和渐进升级。
- 意图识别采用已确认的两阶段顺序：先识别显式模态需求并检索已有索引，再根据服务器验证的证据充分性决定直接回答或创建异步识别任务。
- 意图识别使用“现有主 Agent 的结构化工具路由 + 确定性提示 + 服务端证据门”，不为每条消息额外调用一个独立 LLM 分类器。

### R2. 入库时的轻量发现索引

- 每个新视频必须生成足以参与跨视频检索的时间段级内容索引；只有标题、作者和平台元数据时，不得视为已经完成预处理。
- 内容索引至少需要表达“这个时间段大概讲了或展示了什么”，候选字段包括起止时间、主题、摘要、关键词/实体、语言、内容形态和证据模态；视频级画像只能由时间段索引汇总生成。
- Discovery Segments 采用语义优先切分：优先在话题、章节或明显视觉场景边界断开，设置最长处理范围，缺少语义信号时才退回固定时间窗口，相邻段保留小范围重叠。
- 切分只创建索引记录，不修改或物理切割原视频；每条记录必须保留可跳转的起止时间和原始证据来源。
- 有可用的带时间戳字幕时，优先复用字幕生成时间段级发现索引，不额外运行整段音频或逐帧视觉分析。
- “字幕可用”不能只判断字幕轨是否存在；必须校验 cue 时间合法性、有效文本密度、主要内容区间覆盖和大段缺口。只有片头字幕、零散几句、纯音乐/声音标记或明显缺失主要内容的字幕不能直接完成预处理。
- 字幕质量门槛必须由真实视频评估集确定并版本化；不在规划阶段随意固定一个覆盖率百分比。
- 部分字幕不达标时保留合格字幕区间，只对缺失或低质量的时间区间执行音频与代表帧采样；补齐结果按统一时间轴合并，不对全片重复处理。
- 元数据只能辅助召回和排序，不能单独满足时间戳级搜索的预处理完成条件。
- 没有可用的带时间戳字幕时，无论标题和描述多明确，都必须执行确定性的稀疏音频/画面采样；采样无法形成可靠的时间段索引时自动升级到完整的类型相关处理，不能以“画像不足”等待未来提问作为终态。
- 稀疏采样必须同时覆盖时间分布和内容变化：固定时间锚点保证全片分布，语音活动检测避免抽到静音，场景变化检测与画面去重避免重复抽取相同片头或幻灯片。
- 不能在完全不看画面的情况下可靠判断视频属于幻灯片、软件演示或一般场景。没有有效带时间戳字幕时，少量代表帧的低成本视觉探测属于路由本身的必要输入，不应被描述为路由之后才可能调用的能力。
- 明确区分“视觉探测”和“详细视觉理解”：视觉探测只输出粗粒度内容形态、画面变化和可读文字密度；详细视觉理解才生成 OCR 内容、操作步骤、对象/动作描述和可引用证据。
- 固定采样工作量、升级门槛和最坏处理量必须可配置、可观测，并通过真实视频评估集确定，而不能只依赖模型自报置信度。
- 入库预处理必须异步，并有文件大小、视频时长、并发、重试和超时等技术安全上限；一个模态失败不应阻塞元数据入库和后续恢复。
- 发现索引面向“从很多视频中找候选”，不承诺回答视频细节，也不能作为详细事实回答的充分证据。
- 每个受支持且媒体可访问的视频最终都必须收敛为带时间范围的可搜索索引或明确、可操作的处理失败；只有视频级主题但无法定位时间段不是允许的完成状态。
- 首个落地阶段只对后端能够直接、合规获取媒体的公开视频执行音频/画面采样；登录态、私有、受访问控制或 DRM 媒体不进入首期识别范围。
- 首期公开平台同时覆盖 YouTube 与 Bilibili；两者复用平台无关的识别执行器，但媒体发现、规范化和失败映射保持独立适配器。
- 公开视频获取失败必须收敛为稳定、可重试或明确不可处理的结果，不能尝试导入浏览器 Cookie、登录令牌或绕过平台限制。

### R3. 低成本优先与渐进升级

- 有可用字幕时，默认先检索字幕并用它定位候选时间窗口；只有字幕证据不足且问题确实依赖声音或画面时，才升级到昂贵识别。
- 没有字幕时，音频识别是否自动触发、经用户确认后触发，或只处理问题相关范围，必须形成明确产品规则。
- 图像识别应优先处理有界时间窗口或代表帧，不默认把整段视频逐帧送入视觉模型。
- 保留独立 OCR 执行器，但只在文字密集画面或用户要求精确文字时触发；OCR 负责原文、坐标和置信度，多模态模型负责画面语义和图文关系。
- 不允许对所有代表帧无条件执行完整 OCR；运行前必须完成场景切分、稳定帧选择和感知去重，避免字幕、水印、Logo 与重复幻灯片污染索引。
- 组合问题应能在同一时间轴上合并字幕、ASR 和画面结果，避免不同模态的时间定位互相漂移。
- 第一版详细视觉处理仍以搜索为目标：产物只需支持视频召回、候选排序、时间段定位和简短证据预览，不要求逐镜头叙述、完整动作重建或详尽对象清单。
- 视觉索引粒度应跟随场景/幻灯片变化并合并稳定重复画面；用户追问后才对命中的少量时间窗口做更深理解。
- 首期 ASR、多模态视觉与条件式 OCR 使用托管 API；本地只执行抽帧、场景变化检测、文字密度判断和感知去重，并保留本地 OCR 作为 benchmark/降级对照而非生产默认。
- 托管 ASR、视觉与 OCR 能力必须隐藏在供应商无关适配层之后，业务状态、时间轴证据和搜索索引不能依赖某一家供应商的原始响应格式。
- 首期默认 ASR、视觉与 OCR 供应商必须由真实公开 YouTube/Bilibili 样本基准确定；不在规划阶段仅凭纸面规格锁定。

### R4. 调用时间与分阶段响应

- “找出可能是哪一个视频”的发现请求必须只依赖已落库索引，不能在用户等待期间扫描大量原始视频。
- 对详细问题，已有索引或缓存足以回答时可以直接使用；只要需要任何新的 ASR、视觉或 OCR 识别，就一律创建异步后台任务并立即返回稳定的“正在处理”状态，不在本次请求中等待识别完成。
- 不根据预估视频长度或供应商速度临时决定同步等待；新识别始终异步，以保持固定的调用延迟契约。
- 异步任务必须返回公开任务标识、当前阶段和稳定状态；进度只能表达真实阶段，不能伪造不可靠的完成百分比。
- 识别运行时必须提供服务器本地、可由 operator 直接测试的命令行入口；`recognition probe` 支持公开 YouTube/Bilibili、显式模态和有界时间范围，立即返回 pending/job id 且不写搜索索引。
- CLI 调用与生产路径相同的 runtime service、数据库状态机和队列；要求有效 user 归属，不能指定任意供应商、模型、URL、provider key 或 callback。
- 后台任务通过持久化阶段事件向 Agent 汇报状态，不要求保持原模型请求或通过高频轮询“盯住”任务。
- 用户在等待期间提出新问题时，系统立即中断当前前台等待/状态流并处理新问题，但后台识别继续运行；只有用户明确取消、内容删除或权限失效才取消识别任务。
- 识别完成后，服务端使用原始问题及其可信目标快照自动续答，并把答案关联回原 pending 请求；等待期间的新问题不得污染原问题的续答上下文。
- 多个 pending 问题可以独立完成并按各自原始请求归属返回，不能因完成顺序不同而串错答案。
- 为入库预处理、候选检索、缓存命中回答和冷启动深度识别分别定义延迟目标，具体数值在样本和供应商基准测试后确定。

### R5. 结果复用与生命周期

- 区分“条目存在”“基础文本可检索”“某个模态可用”“按需识别进行中/失败”，避免继续用单一 `ready`/`needs_asr` 状态承载所有能力。
- 发现索引状态至少区分：尚无时间段索引、部分时间段可搜索、完整索引可搜索和处理失败。
- 尚无 Discovery Segments 时，视频只能出现在库存或标题/元数据查询中并标记内容处理中，不能作为内容语义搜索命中。
- 部分 Discovery Segments 已生成时，只允许返回已完成区间，并明确暴露索引覆盖不完整；预处理完成后才视为完整内容搜索结果。
- 识别结果应按视频版本、时间范围、模态、模型/协议版本和内容摘要形成可失效的缓存身份。
- 同一请求的并发、重试和重复提问不得产生重复任务或重复费用；失败后应有稳定的恢复与降级结果。
- 原始音频、视频片段和画面帧采用最短必要保留期；持久化的结构化结果继续受租户和删除边界保护。

### R6. 可信回答与用户控制

- Agent 只能用本轮实际取得且服务器验证过的字幕、ASR 或画面证据回答，不得把模型先验当成视频事实。
- 新证据需要携带视频、时间范围、来源模态和识别方式；前端至少能让用户回到对应视频时间位置。
- 首个落地阶段不实现费用预算、额度、付费准入或逐条费用确认；仍需记录调用量和估算费用，以便后续根据真实用量设计预算控制。
- 上传私有课程媒体仍必须遵守单独的隐私、内容权利和第三方处理边界；不做预算控制不代表放宽隐私授权。
- 路由错误或能力不可用时，应明确说明缺少哪种证据，并给出可执行的下一步，不得静默切换到无依据回答。

### R7. 可观测性与评估

- 记录不含原始内容的路由原因、命中模态、升级次数、处理时长、缓存命中、计费量和失败类别。
- 建立覆盖典型问题的评估集，分别衡量意图分类准确率、无谓昂贵调用率、回答有据率、端到端延迟和成本。
- 上线必须可按租户或功能开关灰度；关闭新路由后，现有字幕入库和文本检索行为保持可用。

## 暂不纳入首轮讨论

- 实时直播理解或实时麦克风转写。
- 人脸识别、身份推断、情绪或敏感属性识别。
- 绕过 DRM、认证、平台访问控制或媒体权利限制。
- 在方案评审前采购供应商、上传私有课程媒体或默认开启付费识别。
- Web 前端弱化、浏览器插件产品化、客户端授权扩展和功能迁移；这些由另一个 Trellis 任务处理。本任务只定义客户端无关的服务端识别与搜索契约。
- 登录态/私有视频的媒体发现、浏览器采样、音频或帧上传和断点续传；未来通过独立任务接入本任务定义的媒体输入边界。

## 验收标准

- [x] 产品负责人确认采用混合模式：入库时建立粗粒度发现索引，详细问题在提问时按需升级。
- [x] 产品负责人确认无字幕视频先做稀疏多模态采样，但采样不确定不能成为终态。
- [x] 产品负责人确认采样不收敛时自动升级到完整的类型相关处理，不要求逐条确认。
- [x] 产品负责人确认没有有效带时间戳字幕时必须把有界代表帧视觉探测作为入库预处理步骤，元数据明确也不能跳过。
- [x] 产品负责人确认采用条件式独立 OCR：文字密集画面和精确文字问题触发，不做全量 OCR。
- [x] 产品负责人确认视觉理解以搜索、候选排序和时间定位为目标，不预先生成详尽视频解说。
- [x] 产品负责人确认首个落地阶段不做费用预算、额度或付费准入控制，只记录用量与估算费用。
- [x] 产品负责人确认元数据不能单独完成预处理；至少需要有效的带时间戳字幕，否则必须执行稀疏音频与画面采样。
- [x] 产品负责人确认字幕必须覆盖主要内容且具有足够有效文本；字幕轨存在本身不是跳过采样的充分条件。
- [x] 产品负责人确认部分字幕只补齐缺失或低质量区间，保留并复用合格字幕，不对全片重新采样。

## 已确认的产品方向

- 第一阶段目标是发现：用户需要能在大量个人视频中定位可能的目标视频，因此入库预处理不可省略。
- 入库预处理只建立粗粒度内容画像，不能为了覆盖未来所有问题而预先完成详细音频和视觉理解。
- 第二阶段目标是深挖：当用户对候选视频提出详细问题时，系统再识别问题意图并按需调用对应模态。
- 发现路径必须快；详细冷路径可以更慢，但需要分阶段反馈，不能让一次问答无限等待。

# Directory Structure

> How the extension (and its shared React UI) is organized.

---

## Overview

Since `c9a4c0e` the only client lives in `extension/` (Manifest V3). One React codebase serves two extension pages: the workspace (`workspace.html`) and the side panel (`sidepanel.html`). Plain-TypeScript modules for the service worker and page injection are compiled by `tsc` without bundling. Source is grouped by product feature, with colocated tests. Shared server contracts and the app shell have their own boundaries.

---

## Directory Layout

```text
extension/
├── manifest.json            # permissions: activeTab, scripting, storage, sidePanel; no popup
├── workspace.html           # vite input → full workspace (library, chat, account, showcase)
├── sidepanel.html           # vite input → side panel (page Q&A, save, login)
├── vite.config.ts           # two inputs; tsc emits worker/page-capture unbundled
├── scripts/                 # clean, copy-static (per-target host permission), audit-package
└── src/
    ├── worker.ts            # service worker: closed Command union (capture, login, READ_PAGE, PLAYBACK, SEEK, SAVE_CAPTURE)
    ├── page-capture.ts      # self-contained MAIN-world adapters (YouTube, Kaltura) + controlPlayer
    ├── protocol.ts          # capture.v1 types, CLIENT_VERSION
    ├── chrome.d.ts          # hand-written minimal chrome typings (only what is used)
    ├── api/
    │   ├── client.ts        # only fetch caller; shared SSE consumer; streamPageQuestion
    │   ├── contracts.ts
    │   ├── openapi.json     # generated from FastAPI
    │   └── schema.d.ts      # generated by openapi-typescript
    ├── app/                 # routing (HashRouter), session gating, shell, browserCompanion constants
    ├── auth/                # LoginPage, EmailLoginFlow (shared with the side panel)
    ├── account/  library/  videos/  showcase/
    ├── chat/                # ChatPage (page_qa threads read-only), MarkdownAnswer, answerText
    ├── sidepanel/           # SidePanel, usePageQa (per-video session), workerApi, deps (chrome adapters), pageIdentity
    ├── ingest/              # ingest status shared by side panel + workspace: ingestCopy (all status copy), ingestModel, IngestProgress (P01b/D02), IngestUnfinished (P01c), ingest.css
    ├── test/                # setup and fake environments (never shipped)
    └── main.tsx
```

Tests are colocated as `*.test.ts` or `*.test.tsx`. The complete browser contract is exported by `scripts/export_web_openapi.py`.

---

## Module Organization

- `api/` is the only UI module that calls `fetch` or reads the CSRF cookie. Extension-runtime requests attach the session Bearer; the worker keeps the capture Bearer.
- Side-panel code reaches Chrome only through `sidepanel/deps.ts` and `sidepanel/workerApi.ts`, so tests inject fakes. Injected page functions stay in `page-capture.ts` and must be self-contained.
- `app/` owns routing, session gating, tenant-cache clearing, and the single top bar.
- Feature folders own page-specific query and mutation orchestration.
- Pure presentation logic stays close to the view using it; all ingest status copy (lifecycle labels, stage labels, failure reasons, placeholders) is centralized in `ingest/ingestCopy.ts`. Never add status strings elsewhere; unknown server values must fall back instead of indexing a closed map.
- Generated files are tracked but never edited manually.

Do not add a generic `utils/`, `services/`, or global state folder until two real consumers require the same responsibility.

---

## Naming Conventions

- React components and files use `PascalCase`.
- Functions, hooks, and non-component modules use `camelCase`.
- Tests use the exact source filename plus `.test`.
- API JSON field names remain the server's `snake_case`; do not create a second translation layer.
- CSS uses readable BEM-like names for component parts and `--modifier` suffixes for states.

## Examples

- `library/VideoCard.tsx` is a small server-state presentation component.
- `videos/VideoDetailView.tsx` separates the testable view from query orchestration in `VideoDetailPage.tsx`.
- `api/contracts.ts` aliases generated schema types instead of duplicating DTO interfaces.
